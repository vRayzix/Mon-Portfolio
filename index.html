UE1 — Administrer les réseaux et l'Internet

Déployer, configurer et dépanner des infrastructures réseau

Définition

En se basant sur les fondamentaux des réseaux, de l'électronique et des systèmes d'exploitation, l'étudiant est capable d'administrer les équipements d'une infrastructure réseau locale et d'assurer la connectivité avec l'Internet.

Composantes essentielles

  • Choisir les outils et méthodes adaptés au contexte (OS, protocoles, topologie)
  • Documenter les configurations et procédures mises en place
  • Respecter les contraintes et règles de l'organisation
  • Garantir le fonctionnement et la disponibilité du réseau

Situations professionnelles visées

  • Déploiement d'un réseau local d'entreprise (VLANs, routage, services)
  • Dépannage et diagnostic de pannes réseau
  • Administration de systèmes Linux/Windows en production
  • Configuration et supervision de services réseau (DHCP, DNS, NAT)

Comprendre l'architecture et les fondements des systèmes numériques, des communications et de l'Internet.

Modèles OSI/TCP-IP étudiés en R1.01. TP Python R1.07. SAÉ 2.02 : streaming audio HTTP vers codec VS1053, décodage MP3/AAC matériel, gestion des flux MQTT.

AC11.03 Acquise

Configurer les fonctions de base d'un réseau local.

SAÉ 1.02 (EVE-NG) : VLANs Directeurs/Utilisateurs/Serveurs/Administration, inter-VLAN router-on-a-stick, DHCP relay (ip helper-address), VTP, spanning-tree. SAÉ 2.01 (GNS3) : VLANs 100/200/300, native VLAN 999, port-security, RIPv2, NAT, ACL.

Interagir avec les systèmes d'exploitation pour la configuration et l'administration des réseaux et services.

Administration Linux en R1.02, R1.08, R2.01, R2.02. SAÉ 2.01 : configuration FTP (anonymous + utilisateurs nommés), Apache (dev+prod), rsync. SAÉ 2.03 : Nginx, Gunicorn, systemd, virtualenv, collectstatic, journalctl.

  • Maîtriser les techniques de mesure et d'audit des transmissions

  • Câblage structuré et installation physique (Cat 7, RJ45, PoE)
  • Mesures de performances et analyse de signaux (RSSI, atténuation)

Réseaux SAÉ 1.02 · S1

Architecture Réseau Succursale

Conception et déploiement d'une infrastructure réseau d'entreprise complète sous EVE-NG avec segmentation VLAN, DHCP relayé et inter-VLAN routing.

AC11.03 · AC11.04 · AC11.05

Voir les détails techniques

Simulateur : EVE-NG avec équipements Cisco (routeurs + switches IOS). Sujet R1.02 — mise en place d'une succursale d'entreprise connectée à un siège.

Architecture réseau

  • Segmentation VLAN : VLAN Directeurs, VLAN Utilisateurs, VLAN Serveurs, VLAN Administration — isolés par politique de sécurité
  • Adressage : masques variables selon VLAN, interconnexions routeurs en /30
  • Inter-VLAN routing : Router-on-a-Stick (sous-interfaces sur le routeur avec encapsulation 802.1Q)
  • VTP : configuration serveur/client pour propagation des VLANs entre switches
  • Spanning-Tree : STP activé pour éviter les boucles de commutation

Services réseau

  • DHCP : déployé initialement sur le switch, puis migré vers un serveur Linux avec relai ip helper-address sur l'interface de chaque VLAN
  • NAT : translation d'adresses sur le routeur border pour l'accès Internet
Topologie logique EVE-NG — Routeurs & Switchs Cisco
Preuve DHCP — attribution dynamique vers postes VPC
Réseaux SAÉ 2.01 · S2

Réseau Multi-Services Avancé

Architecture réseau avancée sous GNS3 avec routage dynamique RIPv2, load-balancing spanning-tree, services FTP/Apache, port-security et ACL.

AC11.03 · AC11.04 · AC11.05

Voir les détails techniques

Simulateur : GNS3. Sujet RT11 — infrastructure réseau multi-sites avec services d'entreprise avancés.

Architecture réseau

  • VLANs : VLAN 100, VLAN 200, VLAN 300, VLAN natif 999 (tagué)
  • Inter-VLAN routing : routage sur commutateur-fed (L3 switching)
  • Load balancing : 3 liens trunk entre switches, équilibrage de charge via spanning-tree (coûts configurés)
  • Routage dynamique : RIP v2 entre routeurs (résumé automatique désactivé)
  • Adressage : interconnexions en /30

Services réseau

  • DHCP : serveur dédié avec plages par VLAN
  • FTP : accès anonyme (lecture seule) + utilisateurs nommés Antoine et Élise avec permissions distinctes
  • Apache : deux environnements (développement et production) avec déploiement par rsync
  • NAT/cloud : translation sur R3 pour accès Internet

Sécurité

  • Port-security : limitation du nombre d'adresses MAC par port, violation en shutdown
  • ACL sur R2 : filtre autorisant HTTP (80), SSH (22), rsync (873) ; reste refusé
  • ACL border : filtre ICMP et HTTP entrant

Dev Infra SAÉ 2.03 · S2

Gestion du Trafic Aérien — Django & MariaDB

Application web de gestion du trafic aérien développée en Django, déployée sur deux VMs Debian (VM-BDD et VM-Django) avec Nginx + Gunicorn et un schéma relationnel 6 entités.

AC13.01 · AC13.02 · AC13.04 · AC13.05 · AC13.06

Voir les détails techniques

Infrastructure (VirtualBox)

  • VM-BDD (Debian) : serveur MariaDB — bind-address 0.0.0.0, utilisateur django_user@'%' avec les droits sur la base django_db
  • VM-Django (Debian) : application Django + serveur Nginx en reverse proxy, Gunicorn WSGI en service systemd
  • Communication entre VMs via réseau interne VirtualBox (NAT + Host-Only)

Modèle de données — 6 entités

  • Aéroports (code IATA, nom, ville, pays)
  • Pistes (numéro, longueur, orientation, aéroport FK)
  • Compagnies aériennes (IATA, nom, pays)
  • Types d'avions (modèle, capacité, constructeur)
  • Avions (immatriculation, type FK, compagnie FK)
  • Vols (numéro, départ FK, arrivée FK, avion FK, horaires, statut)

Application Django

  • base.html : navigation sidebar + barre du haut, thème sombre, hérité par toutes les pages
  • Pages liste : une par entité, avec liens vers détail/édition/suppression
  • Formulaire générique réutilisable : même template pour create/update sur les 6 entités
  • Confirmation de suppression : page dédiée avec retour sécurisé
  • Dashboard : compteurs dynamiques (nb vols, avions, compagnies)
  • Import CSV (import_vols_csv) : lecture UTF-8, correspondance par nom, collecte d'erreurs par ligne, guide de format affiché sur la page
  • Fiche vols (fiche_vols) : filtre aéroport/date/direction + feuille @media print

Déploiement production

  • Service systemd gunicorn.service avec systemctl enable pour démarrage automatique
  • Nginx : bloc location /static/ pour servir les fichiers statiques, proxy_pass vers 127.0.0.1:8000
  • python manage.py collectstatic avec STATIC_ROOT configuré
  • Documentation DEPLOIEMENT.md rédigée par Yassine (procédure reproductible)

Débogage documenté

  • 502 Bad Gateway : diagnostic via ss -tlnp (port 8000 absent) → curl 127.0.0.1:8000 → logs Nginx → Gunicorn non démarré
  • ModuleNotFoundError: pymysql : venv non activé avant gunicorn
  • Conflit Git dans settings.py : marqueurs de fusion non résolus cassant le parse Python
  • systemctl enable : unité non enregistrée car chemin absolu manquant dans le service file
